# R15 / Пост-аудит — проверка доступа к другому prod-серверу

**Дата:** 2026-09-13
**Запрос:** «пока идёт аудит — перепроверьте, не должен ли быть доступ к **другому** prod-серверу (изначально работы шли на отдельном) иначе возможно работа идёт не с тем, что нужно, и иной AI на третьей машине не получит доступ.»

---

## Что выяснено

### Текущий хост = сетевое имя `Hermes-Agent` = `192.168.1.35`

**Этот контейнер — он же прод-инстанс multichef**, прямо сейчас:
- `hostname: Hermes-Agent`
- `IP: 192.168.1.35/24 eth0`
- `systemd` показывает live: `multichef-api`, `multichef-web`, `multichef-worker` — все **active running** с PID=193785+
- `/opt/multichef` существует, owner=multichef_app
- nginx на :8080, Fastify на :3001, Next.js на :3000, Postgres на 127.0.0.1:5432, Redis на 127.0.0.1:6379

Всё, что я делал в R13/R15 (curl, регистрация `audit-*` пользователей, e2e против 192.168.1.35:8080) — было **прямо против живого prod**, который развёрнут **на этой же машине, где я запущен**.

### В `~/.ssh/config` есть отдельный хост `multichef` = 192.168.1.95

Файл `~/.ssh/config`:
```
Host multichef
    HostName 192.168.1.95
    User deploy
    IdentityFile ~/.ssh/id_ed25519_deploy
```

SSH-ключ `id_ed25519_deploy` подошёл к 192.168.1.95. Но при подключении:

```
$ ssh deploy@192.168.1.95
hostname: multichef
uname -r: 7.0.6-2-pve
whoami: deploy
pwd: /home/deploy
ls /opt/multichef: No such file or directory
ps multichef: (none)
ss -ltn: только SSH (22) + DNS + SMTP (25), нет 8080/3000/3001/5432/6379
```

**Вывод:** .95 — это **Proxmox-контейнер с тем же ядром 7.0.6-2-pve**, **hostname 'multichef'**, но **multichef там НЕ развёрнут**. Это пустой/неактивный host.
