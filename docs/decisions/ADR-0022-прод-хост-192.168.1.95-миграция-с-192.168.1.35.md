# ADR-0022: прод-хост — 192.168.1.95 (LXC multichef), миграция с 192.168.1.35

## Status

**Accepted**

## Date

**2026-09-13**

## Context

Прод MULTI-CHEF жил на 192.168.1.35 (Hermes-Agent, 8GB RAM) вместе с
Hermes и его сервисами. Освободился Proxmox LXC 192.168.1.95
(Ubuntu 24.04, 4GB RAM), который можно выделить под проект целиком.
Миграция выполнена по PROMPT-MIGRATE-TO-95.md: bootstrap (.95) → сборка →
миграции → restore дампа с .35 → systemd → backup cron → верификация
(health, страницы, E2E 4/4) → очистка .35.

Нюансы, обнаруженные при миграции:

- Перед turbo build на чистом клоне обязателен `prisma generate` —
  без клиента типы Prisma схлопываются в any и tsc падает на seed-файлах.
- `prisma migrate deploy` не может применять миграции, создающие
  нетрастед-расширения (vector): в PG16 это требует суперпользователя.
  Первичная схема + данные переносятся pg_dump/restore от postgres.
- `deploy.sh` собирает только `--filter=@multichef/web... --filter=@multichef/api...`;
  worker на чистом клоне нужно собрать отдельно (apps/worker/dist).
- Playwright E2E запускать с `E2E_BASE_URL=http://192.168.1.95:8080` —
  origin должен совпадать с CORS_ORIGINS и зашитым NEXT_PUBLIC_APP_BASE_URL.
- В репо добавлены спасённые со старого хоста фикс /fridge/add и правка
  happy-today спеки (0c6a6d1).

## Decision

Единственный прод-хост MULTI-CHEF — **192.168.1.95** (LXC multichef:
Node 24, PostgreSQL 16 + pgvector, Redis 7 (AOF), nginx gateway
:8080/:8443, systemd multichef-{api,worker,web}, backup cron 03:00).
На 192.168.1.35 прод удалён (юниты, nginx-конфиг, /opt/multichef,
/etc/multichef, бэкапы перенесены на .95); сохранены БД PostgreSQL
(холодный архив), dev-чекап /root/workspace/multichef, Redis и Hermes.

## Consequences

### Positive

- Выделенный хост под проект: нет влияния на сервисы Hermes и наоборот
- Чистый воспроизводимый bootstrap задокументирован этой миграцией
- Все исторические бэкапы (.35) собраны на .95 в
  /var/lib/multichef/backups/from-35/

### Negative

- 4GB RAM против 8GB на .35 — следить за памятью при сборке (turbo)
- deploy.sh не собирает worker — держать в голове при чистом клоне
