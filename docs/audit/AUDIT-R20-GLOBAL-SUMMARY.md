## A. Технический — что проверено и чисто

- **MC-107 strict-сверка**: все 19 эндпоинтов с явными схемами сверены с клиентскими payload. Найдены F1 (unit) и подтверждён класс householdName; остальные схемы ⊇ клиентских полей. Схемы в `packages/contracts` (meal-plans/recommendations/budget) — **без** `.strict()`, поэтому лишние поля молча стрипаются (источник F2-маскировки).
- **Schema drift**: `check-schema-drift.mjs` на тестовой БД — OK (только задокументированные DB-only инварианты).
- **RLS**: enabled-таблицы в точности покрыты сервисами с `withTenantContext` (транзакция + `set_config(...,true)`); роль `multichef` без BYPASSRLS/superuser. Дизайн корректный.
- **Безопасность**: gitleaks по 345 коммитам — чисто; `pnpm audit --prod` — 0; сессия HttpOnly+SameSite=Lax, CSRF double-submit (JS-readable по дизайну), throttling 10/min на register/login (e2e реально упирается — работает), error-envelope единый с `redactSecrets`, webhook HMAC+replay-дедуп (e2e зелёные после provisioning секрета).
- **COOKIE_SECURE=false** на проде — оправдано для HTTP-LAN, но зафиксировать как accepted risk до появления TLS.
- **Индексы/транзакции**: tenant-индексы (householdId, expiresAt, status) на месте; критичные пути в интерактивных транзакциях через withTenantContext.
- **Тесты**: API unit 163/163 зелёные локально на main; интеграционные за RUN_DB_INTEGRATION (в CI не входят — принятое решение, см. ci.yml комментарий).
- **CI**: 5 джобов (lint/typecheck/test/build/secret-scan) — адекватно; пробел: deploy-gates не в CI (см. F3).
