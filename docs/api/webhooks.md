# Webhooks (inbound) — спека каркаса, T69-D (E26)

## Endpoint

`POST /api/v1/webhooks/inbound`

Единая точка приёма входящих webhook-доставок (платежи, email-события,
внешние интеграции). Новые интеграции регистрируют обработчик в
`WebhooksService.register(type, handler)` — новые эндпоинты не добавляются.

## Подпись

- Заголовок `X-MC-Signature: sha256=<hex>` — HMAC-SHA256 от **сырого тела**
  запроса (точные байты, без пере-сериализации) ключом
  `WEBHOOK_SIGNING_SECRET`.
- Проверка constant-time (`timingSafeEqual`). Подпись без секрета/с
  неверной подписью -> `401 UNAUTHORIZED`.

## Идемпотентность

- Заголовок/поле `id` события уникально для доставки; повтор с тем же `id`
  отвечает `200 {"received":true}` БЕЗ повторной обработки (in-memory
  дедуп, лимит 10 000 id на инстанс; при горизонтальном масштабировании —
  перенос в Redis).
- Неизвестный `type` — ack `200` + запись в журнал (отправитель не
  получает retry-шторм), обработчик добавляется позже.

## Формат события

```json
{
  "id": "evt_01J...", // уникальный id, >= 8 символов
  "type": "payment.succeeded", // <domain>.<event>, lower_snake
  "occurredAt": "2026-09-16T12:00:00Z",
  "data": {} // произвольный payload события
}
```

## Ответы

| Статус | Код              | Причина                                  |
| ------ | ---------------- | ---------------------------------------- |
| 200    | —                | Событие принято (или повтор)             |
| 400    | VALIDATION_ERROR | Тело не соответствует схеме события      |
| 401    | UNAUTHORIZED     | Нет/неверная подпись, секрет не настроен |

## Статус конфигурации

`GET /api/v1/webhooks/health` -> `{ endpoint, secretConfigured }` (без
секретов) — для runbook-проверок.
