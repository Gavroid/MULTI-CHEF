# План: запуск каталога 2000 рецептов с фото (MULTI-CHEF)

> Дата: 2026-09-13. База плана — аудит качества от 2026-09-13 (269 рецептов на prod `.95`).
> Документ самодостаточен: можно скопировать в новую сессию и выполнять по этапам.

## 1. Цель и критерии готовности (Definition of Done)

| #   | Критерий                           | Значение                                                                           |
| --- | ---------------------------------- | ---------------------------------------------------------------------------------- |
| D1  | Рецептов в статусе `PUBLISHED`     | **2000**                                                                           |
| D2  | Фото (`imageKey` → доступный webp) | 100%                                                                               |
| D3  | Описание (1–2 предложения)         | 100%                                                                               |
| D4  | Инструкции v2                      | ≥4 шагов, суммарно ≥300 символов, у ≥95%                                           |
| D5  | Порция по граммовке                | 100–800 г/порцию у ≥98% (напитки 150–400 мл)                                       |
| D6  | КБЖУ                               | у 100%, `calculationVersion=2`, ккал/порция: напитки 5–500, остальное 120–1200     |
| D7  | Дубликаты названий                 | 0 (точных и near-duplicate с trigram similarity ≥0.9)                              |
| D8  | `IngredientNutrition`              | заполнен для всего справочника (300+ ингредиентов)                                 |
| D9  | Приёмочные проверки                | E2E 6/6, генерация плана `/today/generate` p95 < 3 с при 2000, диск ≤ 8G           |

**Что НЕ входит в план:** правки алгоритма рекомендаций, новые сущности схемы (кроме уникального индекса), мобильные клиенты, localization.

- **Инфраструктура готова частично:**

  - **nginx НЕ отдаёт `/images/`** (404) — нужен `location`.
  - API: cursor-пагинация (createdAt+id) — к 2000 готов.
  - `RecipeSourceType.IMPORTED` уже есть в enum — миграция не нужна.

  - Диск `.95`: 56G свободно (фото ~400 МБ — не проблема). RAM 4G — импорт только потоково, волнами.

## 3. Этап 0 — инфраструктура (~0.5 дня)

```bash
# 0.1 Бэкап перед любыми работами
/opt/multichef/infrastructure/scripts/backup.sh

# 0.2 Каталог фото + nginx
mkdir -p /var/www/multichef-images/recipes && chown -R www-data:www-data /var/www/multichef-images
# в /etc/nginx/sites-available/multichef.conf ДОБАВИТЬ location (в оба server: 8080 и 8443):
#   location /images/ {
#       alias /var/www/multichef-images/;
#       expires 30d;
#       add_header Cache-Control "public, immutable";
#   }
nginx -t && systemctl reload nginx
curl -s -o /dev/null -w "%{http_code}" http://127.0.0.1:8080/images/recipes/<тест>.webp   # → 200 после 3.4
```

- **0.3 Уникальность названий.** Миграция: `CREATE UNIQUE INDEX "Recipe_title_lower_key" ON "Recipe" (lower(title));`
  плюс `CREATE INDEX "Recipe_title_trgm_idx" ON "Recipe" USING gin (title gin_trgm_ops);` (для near-dup поиска).
  Сид-раннер переводится с `findFirst` на upsert по `lower(title)`.
- **0.4 `prisma generate` перед любой сборкой** (см. ADR-0022) и сборка worker: `pnpm turbo run build --filter=@multichef/worker...`.

## 4. Этап 1 — стандарт качества и справочник (~1 день)

### 4.1 Заполнить `IngredientNutrition` (per 100 г/мл: kcal, proteinG, fatG, carbsG)

- Источник: `packages/database/src/seed/nutrition/nutrition-data.ts` (уже есть для 300 ингредиентов).
- Скрипт `scripts/backfill-ingredient-nutrition.ts`: upsert всех 300 → выборочная сверка 20 позиций с Open Food Facts / USDA (вручную, таблица в отчёте).
- Это разблокирует: пересчёт КБЖУ любых рецептов и работу пользовательских рецептов.

### 4.2 `servingGrams`

- Формула: `sum(RecipeIngredient.grams) / servings`. Включить в расчёт КБЖУ, `calculationVersion → 2`, полная пересчётная миграция всех рецептов.

### 4.3 Валидатор `scripts/validate-recipes.ts` (единые ворота для любого импорта)

Проверяет каждый рецепт (JSON-карточка), выводит отчёт `валид / ошибок по правилам`:

| Правило     | Порог                                                                                                                                         |
| ----------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Поля        | title (уникальный, ru), category, cuisine, season, mealTypes ≥1, difficulty 1–3, servings 1–12, prep+cook 5–240 мин, description 80–250 симв. |
| Ингредиенты | ≥3; `unit ∈ {G, ML, PIECE}`; `grams > 0`; каждый `ingredientId` резолвится в справочник; сумма граммов > 0                                    |
| Порция      | 100–800 г/порцию; напитки 150–400 мл                                                                                                          |
| КБЖУ        | напитки 5–500 ккал/порцию, остальное 120–1200; protein+fat+carbs × 4/9 в ±25% от kcal                                                         |
| Шаги        | ≥4; суммарно ≥300 символов; ≥1 шаг с числом (время/температура/граммы); шаги не повторяются                                                   |
| Дедуп       | `lower(title)` уникален + trigram similarity < 0.9 ко всем существующим                                                                       |
| Теги        | `category:` ровно 1, `cuisine:` ≥1, `season:` ≥1                                                                                              |

- Юнит-тесты валидатора (happy + по одному фейлу на правило).

### 5.2 Формат датасета

- `data/recipes/wave-N/<slug>.json` — одна карточка = один файл (стриминг, не монолит).
- Схема карточки = текущий `RecipeSeed` + `description` + `imagePrompt` + `imageAlt`.
- Хранится в git → ревью, откат, воспроизводимость.

### 5.3 Текстовая генерация `scripts/generate-recipes.ts`

- Вход на карточку: категория + кухня + ключевой ингредиент **из справочника 300** (новые ингредиенты запрещены; если нужны — карточка уходит в очередь `data/ingredient-requests/`, справочник расширяется отдельным шагом с КБЖУ).
- Промпт: JSON-схема, температура 0.7, 2–3 few-shot примера из существующих рецептов, запрет повторять существующие названия (передаём список слагов волны).
- Fix-loop: карточка → валидатор → ошибки обратно в LLM, максимум 3 итерации, иначе в `data/quarantine/`.
- Инструкции: отдельный проход «раскрыть скелет» (пошагово, с граммами, температурой, временем — ориентир 4–8 шагов, 300–700 символов).
- Граммовки: эвристики порций по категории (супы 300–400 г, основные 250–350, салаты 150–250, каши 250–300, напитки 200–300 мл) + `PIECE`-ингредиенты по штукам.
- Оценка объёма: ~1731 карточка × 1–2K токенов ≈ 2–4М токенов (дёшево, гонять батчами по 50, с ретраями и чекпойнтами).

### 5.4 Фото-пайплайн `scripts/generate-images.ts`

- Генерация: фотореалистичный промпт из title + 3–5 главных ингредиентов + ЕДИНЫЙ стиль (естественный свет, ракурс 45°, деревянный стол, порция на тарелке) — чтобы каталог выглядел как один проект.
- Пост-обработка: основной `1200×900 webp q80` (~100–150 КБ) + thumb `480×360 webp` (~20–30 КБ) → `/var/www/multichef-images/recipes/{slug}.webp` и `{slug}_480.webp`.
- `imageKey = /images/recipes/{slug}.webp`, `imageAlt` — короткое описание вида «{title} — готовое блюдо».
- QA: после каждой волны — контактный лист (сетка превью) просматривается человеком; битые/некрасивые перегенерируются точечно.
- Бюджет: 2000 × ~130 КБ ≈ **260 МБ** + thumb ~50 МБ. Генерация ~5–15 с/фото → 3–8 часов суммарно, батчами с ретраями.

### 5.5 Расчёт КБЖУ и импорт

- КБЖУ: `@multichef/nutrition` по `IngredientNutrition` → `RecipeNutrition` (`calculationVersion=2`).
- Импорт `scripts/import-recipes.ts`: upsert по `lower(title)`, `status=DRAFT`, полная замена `RecipeIngredient` (как текущий сид), запись nutrition.
- Публикация волны: после QA — `UPDATE "Recipe" SET status='PUBLISHED' WHERE id = ANY($wave_ids)`.

## 8. Этап 5 — приёмка (готовые контрольные запросы)

```sql
-- D1: count
SELECT count(*) FROM "Recipe" WHERE status='PUBLISHED';                          -- 2000
-- D2: фото
SELECT count(*) FILTER (WHERE "imageKey" IS NULL) FROM "Recipe";                 -- 0
-- D5/D6: порции и ккал
SELECT count(*) FILTER (WHERE portion NOT BETWEEN 100 AND 800) FROM
  (SELECT r.id, sum(ri.grams)/r.servings portion FROM "Recipe" r
   JOIN "RecipeIngredient" ri ON ri."recipeId"=r.id GROUP BY r.id, r.servings) p; -- <40 (2%)
-- D6: version
SELECT count(*) FROM "RecipeNutrition" WHERE "calculationVersion" < 2;           -- 0
-- D8: справочник
SELECT count(*) FROM "Ingredient" i WHERE NOT EXISTS
  (SELECT 1 FROM "IngredientNutrition" n WHERE n."ingredientId"=i.id);           -- 0
-- D7: near-dup
SELECT count(*) FROM (SELECT t FROM
  (SELECT lower(title) t FROM "Recipe") a JOIN (SELECT lower(title) t FROM "Recipe") b
  ON a.t < b.t AND similarity(a.t, b.t) >= 0.9) x;                               -- 0
```

Плюс: E2E `E2E_BASE_URL=http://192.168.1.95:8080 pnpm --filter @multichef/web test:e2e` → 6/6;
замер p95 `/today/generate`; `curl -o /dev/null -w "%{http_code}"` на 20 случайных `imageKey` → 200;
`df -h /` ≤ 8G занято.

## 9. Риски и меры

| Риск                                             | Мера                                                                                |
| ------------------------------------------------ | ----------------------------------------------------------------------------------- |
| LLM придумывает ингредиенты вне справочника      | жёсткий резолв по `ingredientId`, иначе quarantine + очередь расширения справочника |
| Семантические дубли («Борщ» / «Борщ украинский») | trigram-порог + ручная QA-выборка 5% волны                                          |
| Битые/некрасивые фото                            | UI уже имеет fallback; контакт-лист после каждой волны, точечная перегенерация      |
| 4GB RAM при импорте                              | потоковая обработка по одному файлу, волны ≤800                                     |
| Долгий сид при 2000 (findFirst без индекса)      | индекс `lower(title)` на этапе 0 + upsert                                           |
| Стоимость/лимиты генерации                       | чекпойнты, ретраи, батчи 50; текст дёшев, фото — самый долгий этап (3–8 ч)          |
